Webinar Gap Analysis

EA-SYS webinar capability vs BigMarker, Zoom Webinars / Zoom Events, ON24, RingCentral Events, Livestorm.
Created: 2026-07-27 · Method: exhaustive read of the webinar code surface at HEAD + web research of current vendor capability. Status: assessment only — nothing here is a committed build.

Bottom line — we cannot do what BigMarker/Zoom Events do today, and the gap is not where you would guess.

The event-management wrapper around our webinars is genuinely competitive and in several places ahead of BigMarker's base tier (paid ticketing, white-label on our own domain, UTM attribution, registration-gated replay, certificates). The hole is the live experience: we do not own one. We either rent it from Zoom or we do not have it.

1. The fork that decides everything

Event.settings.webinar.viewingMode has two values, and they share almost no capability. This is the single most important fact about our webinar architecture, and it is currently unresolved.

mode: zoom Zoom SDK embed

  • Zoom Component View embedded in our page (zoom-web-embed.tsx)
  • Chat, Q&A (upvote + comment + anonymous), polls, reactions, raise hand, captions, breakouts, screen share, multi-presenter, host mute/remove — all native, all free to us
  • We explicitly force Q&A on at webinar-create: src/lib/zoom/meetings.ts:85-94
  • Capped by the Zoom plan (500 attendees base)
  • Every attendee costs Zoom seat economics

mode: hls Self-hosted RTMP→HLS

  • MediaMTX on the box → nginx /stream/ → CloudFront
  • Zero interactivity. A <video> with a mute button (live-player.tsx)
  • No chat, no Q&A, no polls, no reactions, no hand-raise
  • Scales to ~5,000+ at near-zero marginal cost
  • The console UI says this out loud in the viewing-mode picker

Read this as the strategic question: in Zoom mode we inherit Zoom Webinars' entire live stack for free, but we are capacity-capped and paying Zoom per attendee. In HLS mode we get the scale and the margin — and the attendee stares at a video with no way to interact.

Everything else in this document is downstream of which of those two we decide to invest in.

4. Gaps, banded by priority

Band A Table stakes, cheap, no architecture risk

  • No ICS / add-to-calendar on any webinar email or page. All five vendors have it. Most embarrassing item on the list; roughly a day of work.
  • No custom registration fields. Attendee.customFields is a JSON column nothing writes — no builder UI, not on the public form.
  • No Q&A / poll export. Attendance exports to CSV; engagement does not. The Q&A card has no export button.
  • Peak concurrent + total watch time computed and never rendered. Pure UI work.
  • No drop-off curve despite holding every join/leave segment.

Band B Parity gaps

  • No outbound webhooks. Integration table stakes.
  • No Zoom webhooks. Everything is poll-based, so recording/attendance always lag by 5–10 minutes and we burn API calls on empty polls.
  • No transcripts or captions ingested — Zoom generates them and we throw them away.
  • No no-show branch in the sequence; no auto-send-replay-to-early-leavers (a BigMarker ★ we have the data for).
  • No handouts/resources surface on the public session page.

Band C Real differentiators we lack — deliberate build/buy decisions

  • Simulive and evergreen. Zero occurrences in the codebase. Evergreen is BigMarker's category-defining feature and Zoom has no answer to it.
  • In-session offers / CTAs. BigMarker's conversion primitive.
  • Engagement / lead scoring. The biggest single missing cluster; ON24 owns it.
  • On-demand content hub. No library, no evergreen replay landing pages.
  • Native interactivity in HLS mode — see §1. This is the largest single build in this document.

5. Defects, dead code and one security issue found during the read

MediaMTX has no publish authentication. mediamtx.yml sets paths: all: {source: publisher} — anyone who learns a stream key can hijack the live broadcast. The July 27 hardening batch gated the key from readers (stream-status no longer returns streamKey), but the ingest side remains open. Worth closing before any HLS-mode event that matters.

6. The highest-value gap: watch-time-gated certificates

Certificate auto-issue currently gates on surveyCompletedAt (src/lib/certificates/auto-issue.ts) — not on watch time.

ON24's category-defining feature is criteria-based certification: auto-issue when "watched N minutes AND passed the knowledge check". We already store every join/leave segment in ZoomAttendance, we already compute per-attendee watch seconds, and we already have a full certificate engine with CME hours and serials. We simply do not connect them.

For a medical-education business this is the highest-value item in this entire document, and it is the one place where we would be copying ON24 rather than BigMarker. It is already flagged in docs/ROADMAP.md under "Virtual attendance certificates".

7. Ranked recommendations

Not a proposal to start building — the standing posture is stabilization-first until several real conferences have run on EA-SYS. This is the ordered list for when that changes.

#WorkSizeWhy this order
1 Watch-time-gated certificates (+ optional knowledge check) S Highest ROI on the list. Uses data we already hold, hits the CME business directly, and closes the one gap where we would lead rather than follow.
2 Band A cleanup — ICS, custom registration fields, Q&A/poll export, surface peak-concurrent + drop-off curve S each Cheap, independent, no architecture risk. ICS in particular is indefensible to be missing.
3 Close the MediaMTX publish-auth hole + remove the four dead settings S Security + honesty. Both are small and both are currently misleading someone.
4 Decide the HLS interactivity question — native chat + Q&A + polls for HLS mode L The fork from §1. If we ever want to run a 5,000-person webinar on our own economics, this is mandatory. It is what determines whether we are a webinar platform or a Zoom front-end.
5 Simulive / evergreen + on-demand content hub L Only worth it if webinars become a marketing product rather than a delivery mechanism. Large, and it presumes #4.
